# Revised v3 evidence harness

The original plan/mapping and `docs/evidence/paper85/v3/` are historical and
immutable. See `spec-v3/review-amendment.v3.1.md` for post-review changes and
expected outcomes. No production Solidity source is changed.

Install the repository's pinned dependencies (viem 2.55.10 in `apps/api`) and
Foundry 1.7.1; make `forge` and `anvil` available on PATH. Supply an explicit
solc 0.8.30 executable. Governed execution inputs must be committed first.

```sh
node --test experiments/paper85-evaluation/scripts/v3/*.test.mjs
node experiments/paper85-evaluation/scripts/v3/run-revision.mjs /absolute/path/to/solc-0.8.30
node experiments/paper85-evaluation/scripts/v3/verify-run.mjs /absolute/path/to/sealed/run
```

The suite runs sequentially. It creates a unique directory below
`docs/evidence/paper85/v3-revision/`; it never resumes or overwrites a run.
Only a directory with `manifest.json` status `complete` is publication evidence.
Failures retain `FAILED.json` and partial inputs for diagnosis. Do not mix their
files with a completed run. Runners require the suite-assigned `PAPER85_RUN_DIR`.

Module boundaries:

- `common.mjs`: chain operations, verified EVM rejection classification, decoding.
- `evidence.mjs`: source guard, isolation, append-only receipts and file sealing.
- `build.mjs`: pinned build and independent literal-input bytecode reproduction.
- `audit-pricing.mjs`: pure case-policy NAV audit, shared by runner and verifier.
- `audit-case.mjs`: pure Q1–Q7 queries and explicit expectation checks.
- `run-*.mjs`: experiment orchestration; `probe-*.mjs`: disclosed counterexamples.
- `verify-run.mjs`: offline raw-log replay, view/receipt/storage/timing checks.

Evidence layout:

- `run.json`: code commit, governed file hashes, actual host, chain configuration.
- `build/`: compiler executable hash/version, effective Foundry configuration,
  literal standard-JSON inputs/outputs (gzip), ABI/bytecode artifacts.
- `chains/*.jsonl.gz`: chain configuration; deployment/call inputs, mined
  envelopes/receipts/block timestamps, deployed runtime, simulated rejections,
  snapshot boundaries and final contract storage maps. Snapshot-based comparator
  tests can reuse block numbers; scenario markers preserve those boundaries.
- `scale/*/replay.json.gz`: genesis, raw/decoded logs, exact JSONL index string,
  checkpoints with independent contract views, operations, final replay state,
  reference checks and all timing samples. Tape links bind operations to receipts.
- `case/`, `canonical/`, `next-nav/`, `trajectories/`: replay inputs and projections
  for the remaining experiments. `A`–`E` JSON files contain derived results.
- `verification.json`: offline checks; `manifest.json`: hashes of every file.

Compression is lossless. Index byte counts refer to the archived uncompressed
JSONL string, storage counts to nonzero contract slots, and replay timing to
the pure loop only. Hashes provide internal integrity/provenance, not external
attestation. A case-policy result is not a regulatory certification.

## Candidate verification repairs

The measurement archive was generated by commit
`347ea2636dce91b5381f72c084006de8aea971aa`. Subsequent verifier changes do not
change its 101 sealed files or its original `verification.json`. An external
verification report records both measurement identity and verifier identity.
An uncommitted review candidate has `verifier.commit: null`, a base commit,
`governedInputsDirty: true`, and a hash for every current governed input,
including untracked new source files. This does not bypass the clean-source
requirement for generating new measurement runs.

`sourceIdentity` owns the single governed-path list. Its optional repository
root and reference parameters let tests use a disposable Git repository with
actual frozen-source and preregistration checks; tests never rewrite this
checkout's runner, compiler configuration or lockfile. Production defaults keep
the original references. `startAnvil` writes its initial evidence record before
starting the node. `record` rejects missing journal paths; rejection tests pass
an explicit in-memory recorder instead of silently suppressing evidence.

Case correction relationships are derived from identical `asOf` dates. Under
this disclosed stylized case policy, every later version of a date is a
correction, Q1 excludes these versions from new regular dealing batches, and Q2
uses the last available correction for retrospective impact. This is not a
general regulatory classification. Legacy archived correction-index lists are
checked against the derived relationships rather than used to select them.

`spec-v3/case-expectations.postreview.json` is a machine-readable regression
oracle transcribed from the preserved plan and results. It is explicitly
post-review, not preregistration or independent empirical validation. The new
case verifier reconstructs every Q1–Q7 answer and detail list, including the Q2
affected set, and compares all answers with the archived summary. Complete
movement/delay/affected arrays and selected other values must also match the
expectation file. Separate negative fixtures cover repeated corrections,
missing affected businesses, bad eligibility, pause boundaries, missing
payloads, wrong checkpoints and incorrect delay durations.

For a historical remeasurement, create a separate checkout of the measurement
commit (example path must not already exist), install its pinned prerequisites,
and run the original suite there:

```sh
git worktree add --detach ../paper85-measurement-347ea26 347ea2636dce91b5381f72c084006de8aea971aa
cd ../paper85-measurement-347ea26
node experiments/paper85-evaluation/scripts/v3/run-revision.mjs /absolute/path/to/solc-0.8.30
```

To verify an existing run with the candidate code, use an output path outside
the sealed directory. Reports refuse overwrite and cannot be placed inside the
input run:

```sh
node experiments/paper85-evaluation/scripts/v3/verify-run.mjs /absolute/path/to/sealed/run /absolute/path/outside/verification-candidate.json
```

Coverage is recorded in the report. Case Q1–Q7 and raw replay/scale checks are
recomputed. Comparator classification counts remain consistency checks of
archived observations; EVM execution, compiler builds, timings and the revoked
holder probe are not rerun by this offline verifier. Sharing query functions
checks consistency; independent expected fixtures and mutation tests are still
needed to catch shared implementation mistakes.
